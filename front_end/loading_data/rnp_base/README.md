# RNP BASE - Единая база данных (4 уровня агрегации)

## 📋 Описание

**RNP BASE** - это новая функция для создания единого листа "База РНП" в Google Sheets с 4 независимыми уровнями агрегации данных:

1. **LEVEL 1: Артикулы (vendor_code)** - детальные данные по каждому артикулу за каждый день
2. **LEVEL 2: Предметы (category_wb)** - агрегированные данные по категориям за каждый день
3. **LEVEL 3: Склейки (imt_id)** - агрегированные данные по склейкам за каждый день
4. **LEVEL 4: Магазин** - агрегированные данные по всему магазину за каждый день

Все 4 уровня хранятся в **одном листе** "База РНП" и фильтруются по признаку ("Артикул", "Предмет", "Склейка", "Магазин").

## 🔧 Компоненты

### 1. **header_config.py**
Явное маппирование хедеров Google Sheets на атрибуты БД:

```python
HEADER_MAPPING = {
    "A": {"name": "Дата", "source": "date", ...},
    "B": {"name": "Признак", "source": "признак", ...},
    "C": {"name": "Имя", "source": "имя", ...},
    # ... и т.д.
}
```

Параметры конфигурации:
- `DAYS_BACK` = 90 (период выборки)
- `SHEET_NAME` = "База РНП"
- `BACKUP_SHEET_NAME` = "backup_rnp"

### 2. **structure_validator.py**
Валидирует:
- Корректность `header_config.py`
- Соответствие хедеров Google Sheets конфигурации

### 3. **rnp_base_fetcher.py**
Fetch данных:
- `fetch_raw_data_for_level_1()` - детальные данные (без GROUP BY)
- `fetch_raw_data_for_aggregation()` - агрегированные данные (с GROUP BY)
- `fetch_current_sheet_data()` - текущие данные для backup
- `fetch_headers_from_sheet()` - хедеры из Google

### 4. **rnp_base_aggregator.py**
Построение 4 уровней:
- `build_level_1_articulы()` - артикули (компоновка без агрегации)
- `build_level_2_предметы()` - предметы (GROUP BY category_wb, date)
- `build_level_3_склейки()` - склейки (GROUP BY imt_id, date)
- `build_level_4_магазин()` - магазин (GROUP BY date)

### 5. **rnp_base_transformer.py**
Трансформирует данные в формат Google Sheets:
- `transform_to_sheet_format()` - преобразует List[Dict] в List[List]

### 6. **rnp_base_writer.py**
Работа с Google Sheets:
- `check_or_create_sheet()` - проверка/создание листа
- `clear_sheet_data()` - очистка листа
- `write_headers()` - запись хедеров
- `write_data_rows()` - запись данных
- `create_backup()` - создание backup листа

### 7. **rnp_base_orchestrator.py**
Главная функция:
- Валидация конфигурации
- Fetch данных
- Агрегация
- Трансформация
- Создание backup
- Запись данных

## 📊 Хедеры (18 колонок)

```
A: Дата
B: Признак                      (Артикул / Предмет / Склейка / Магазин)
C: Имя                          (vendor_code / category_wb / imt_id / "Магазин")
D: Заказы
E: Сумма заказов
F: Расход на рекламу
G: ДРР                          (вычисляемый: E/F)
H: Клики общие
I: В корзину
J: Конверсия в корзину
K: Конверсия в заказ
L: CPM
M: Рекламные просмотры
N: Рекламные клики
O: CTR
P: CPC
Q: Остатки WB                   (только для Level 1)
R: Цена одного заказа
```

## 🔄 Цикл выполнения

```
1. Валидация конфигурации
   ↓
2. Fetch хедеров из Google
   ↓
3. Fetch текущих данных для backup
   ↓
4. Fetch сырых данных из Supabase (4 уровня)
   ├─ LEVEL 1: vendor_code (без GROUP BY)
   ├─ LEVEL 2: category_wb (GROUP BY category_wb, date)
   ├─ LEVEL 3: imt_id (GROUP BY imt_id, date)
   └─ LEVEL 4: магазин (GROUP BY date)
   ↓
5. Агрегация каждого уровня
   ↓
6. Объединение всех 4 уровней
   ↓
7. Трансформация в Google Sheets формат
   ↓
8. Создание backup листа
   ├─ Проверка листа backup_rnp
   ├─ Запись хедеров
   └─ Запись текущих данных
   ↓
9. Очистка основного листа
   ↓
10. Запись хедеров в основной лист
   ↓
11. Запись новых данных
   ↓
12. Итоговый отчёт
```

## 🚀 Запуск

python3 front_end/loading_data/rnp_orchestrator.py

0. RNP BASE (база данных)

3. РНП по предметам
4. РНП по магазину

python3 front_end/loading_data/rnp_base/rnp_base_orchestrator.py

## 🔐 Backup

Перед каждым обновлением создается backup:

1. **Лист "backup_rnp"** - создается автоматически если не существует
2. **Очистка** - предыдущие backup данные удаляются
3. **Запись** - текущие данные из "База РНП" сохраняются в "backup_rnp"

## ⚠️ Безопасность

**Требования БД:**
- БД должна быть доступна по URL из `api_keys.SUPABASE_DB_URL_LOCAL`
- Таблицы: `adv_params`, `cr_daily_stats`, `products`

**Требования Google Sheets:**
- Учетные данные в `api_keys.GOOGLE_CREDENTIALS_INFO`
- ID таблицы в `api_keys.RNP_REPORT_ID`
- Лист "База РНП" должен существовать (или будет создан)

## 📝 Примечания

1. **Независимость уровней** - каждый уровень обрабатывается отдельно, без смешивания данных
2. **Ежедневные данные** - сохраняются данные за каждый день (не суммируются за весь период)
3. **Динамические хедеры** - маппинг хедеров можно менять в `header_config.py`
4. **NULL значения** - для агрегированных уровней `stocks_wb` = NULL

## 🔗 Интеграция

RNP BASE входит в состав оркестратора РНП и запускается **первым** перед остальными функциями.

Это обеспечивает:
- Единую актуальную базу данных
- Данные готовы для других РНП функций
- Backup данных перед любыми операциями
